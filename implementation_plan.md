# Implement Scalable API Integration for LLM Models

This plan outlines the architecture and steps required to introduce multiple API-based LLMs into the project, making it scalable to support 4-5 (or more) models. Users will be able to switch between these models dynamically from the UI.

## User Review Required

> [!WARNING]
> This plan introduces API integrations which require valid API keys to function. You will need to obtain API keys for the providers you wish to use (e.g., OpenAI, Google Gemini, Groq, Anthropic) and add them to a `.env` file.

> [!IMPORTANT]
> The current system relies entirely on a local Hugging Face model (`TinyLlama`). We will keep a "Local" option as a fallback, but the primary mechanism will shift to external APIs for better performance and quality. We'll add the `openai`, `google-generativeai`, and `requests` libraries to `requirements.txt`. Are you okay with adding these dependencies?

## Open Questions

1. **Which specific 4-5 models do you want to start with?** My proposal is:

   - Google Gemini (gemini-1.5-flash)
   - Groq (llama3-8b-8192 - excellent for fast inference)
   - Anthropic (claude-3-haiku)
   - Local Fallback (TinyLlama - existing)
   *Let me know if you prefer a different set of models.*
2. **Library Approach:** Should we use the official SDKs (like `openai`, `google-generativeai`) or manage everything via raw `requests` to minimize dependencies? My recommendation is to use the official SDKs for stability.
